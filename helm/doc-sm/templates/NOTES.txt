This release stores nothing. A story map lives in the .storymap file the visitor
exports, and nothing about it reaches this pod — there is no database, no volume
and no registry call, so a pod can be deleted at any moment without losing work
that was already exported. Work that was *not* exported lives only in the
visitor's tab, which is what the board's unload warning is for.

Reminder: image.tag is pinned with pullPolicy: Never in values-local.yaml, so a
rebuilt image under the same tag leaves the running pods untouched. After
rebuilding, force them over:
  kubectl rollout restart deployment/{{ include "doc-sm.fullname" . }} -n {{ .Release.Namespace }}

or just run helm/doc-sm/deploy.sh, which does all three steps.
