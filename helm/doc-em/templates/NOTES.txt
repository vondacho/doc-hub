Verify the release:

This release stores nothing. A map lives in the .examplemap file the visitor
exports, and nothing about it reaches this pod. A pod can be deleted at any
moment without losing work that was already exported. Work that was *not*
exported lives only in the visitor's tab, which is what the board's unload
warning is for — and in a session that is the red cards, which the feature file
cannot carry either.

Reminder: image.tag is pinned with pullPolicy: Never in values-local.yaml, so a
rebuilt image under the same tag leaves the running pods untouched. After
rebuilding, force them over:
  kubectl rollout restart deployment/{{ include "doc-em.fullname" . }} -n {{ .Release.Namespace }}

or just run helm/doc-em/deploy.sh, which does all three steps.
