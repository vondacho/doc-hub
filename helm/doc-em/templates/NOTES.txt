Verify the release:

Nothing about a map reaches this pod. The map lives in the .examplemap file the
visitor exports, and the board keeps a copy in their browser's local storage —
this side of it holds neither. A pod can be deleted at any moment without losing
anybody's work.

Work that was never exported lives in that one browser, which is what the board's
unload warning is for: a copy in one browser is insurance, not an artefact. In a
session that is mostly the red cards, which the feature file cannot carry either.

Reminder: image.tag is pinned with pullPolicy: Never in values-local.yaml, so a
rebuilt image under the same tag leaves the running pods untouched. After
rebuilding, force them over:
  kubectl rollout restart deployment/{{ include "doc-em.fullname" . }} -n {{ .Release.Namespace }}

or just run helm/doc-em/deploy.sh, which does all three steps.
